# Typing Trainer - Database Specification & Architecture
**Database Engine:** SQLite 3  
**Migration Framework:** Flyway  
**ORM / Persistence:** Spring Data JPA / Hibernate 6  
**Dialect:** Community SQLite Dialect (`org.hibernate.community.dialect.SQLiteDialect`)  
**Target Platform:** Windows Desktop (Offline-First)  
**Last Updated:** 2026-11-19  

---

## 1. Overview & Architectural Principles

Typing Trainer is an offline-first Windows desktop application. All user progress, session telemetry, lesson milestones, and preferences are persisted locally on the user's workstation.

### Core Persistence Rules:
1. **Single-User Local Storage:** The database is single-user and resides exclusively in the user's local application data directory. No cloud database or remote synchronization is involved.
2. **Flyway Migration Exclusivity:** All schema definitions, table creation, and modifications are managed exclusively via versioned Flyway SQL migration scripts located in `backend/src/main/resources/db/migration/`. JPA entity auto-DDL is strictly disabled (`spring.jpa.hibernate.ddl-auto: validate`).
3. **SQLite Single-Writer Concurrency:** SQLite supports concurrent readers but only one writer at a time. The backend configures HikariCP with `maximum-pool-size: 1` to serialize all writes through a single dedicated connection, avoiding `SQLITE_BUSY` lock contention.
4. **Write-Ahead Logging (WAL):** SQLite WAL mode (`PRAGMA journal_mode = WAL;`) is recommended for production to allow non-blocking concurrent reads during write operations.
5. **No Per-Keystroke Persistence:** Keystroke streams are processed in-memory in the React frontend. The database receives writes only when a session reaches terminal state (completed or aborted).

## 2. Database Location & File Handling

In production, the SQLite database file resides outside the application installation directory in the user's Windows AppData directory:

```text
%LOCALAPPDATA%\TypingTrainer\data\typing-trainer.db
```

Resolved in Spring Boot configuration (`application.yml`):
```yaml
spring:
  datasource:
    url: jdbc:sqlite:file:${user.home}/AppData/Local/TypingTrainer/data/typing-trainer.db
    driver-class-name: org.sqlite.JDBC
    hikari:
      maximum-pool-size: 1
```

For automated testing (`src/test/resources/application.yml`), an isolated database file is used:
```yaml
spring:
  datasource:
    url: jdbc:sqlite:file:target/test-typing-trainer.db
```

## 4. Table Definitions (V1 Baseline)

### 4.1 Table: `typing_sessions`
Stores completed typing test and practice sessions.

```sql
CREATE TABLE typing_sessions (
    id TEXT PRIMARY KEY NOT NULL,
    gross_wpm REAL NOT NULL,
    net_wpm REAL NOT NULL,
    accuracy REAL NOT NULL,
    total_errors INTEGER NOT NULL,
    raw_characters INTEGER NOT NULL,
    correct_characters INTEGER NOT NULL,
    duration_seconds REAL NOT NULL,
    passage TEXT NOT NULL,
    completed_at TEXT NOT NULL
);
```

#### Column Specifications:
- `id` (`TEXT`, PK): UUIDv4 string generated by the client prior to submission for idempotency. In JPA, mapped via `@JdbcTypeCode(SqlTypes.VARCHAR)` on `java.util.UUID`.
- `gross_wpm` (`REAL`): Total keystrokes per 5 characters per minute.
- `net_wpm` (`REAL`): Gross WPM minus uncorrected errors per minute.
- `accuracy` (`REAL`): Percentage of correct keystrokes (`0.0` to `100.0`).
- `total_errors` (`INTEGER`): Total number of incorrect character attempts.
- `raw_characters` (`INTEGER`): Total character count typed.
- `correct_characters` (`INTEGER`): Count of correctly typed characters.
- `duration_seconds` (`REAL`): Total test duration in seconds.
- `passage` (`TEXT`): The practice text passage (up to 10,000 characters).
- `completed_at` (`TEXT`): ISO-8601 UTC timestamp (e.g. `2026-11-19T12:00:00Z`). In JPA, mapped via `@JdbcTypeCode(SqlTypes.VARCHAR)` on `java.time.Instant`.

### 4.2 Table: `user_settings`
Key-value store for application configuration and user preferences.

```sql
CREATE TABLE IF NOT EXISTS user_settings (
    key TEXT PRIMARY KEY NOT NULL,
    value TEXT NOT NULL
);
```

#### Supported Keys:
- `theme`: Active color theme (`SYSTEM`, `DARK`, `LIGHT`).
- `sound_enabled`: Sound effects toggle (`true`, `false`).
- `mechanical_switch`: Switch audio profile (`BLUE_CLICKY`, `BROWN_TACTILE`, `RED_LINEAR`).
- `default_duration`: Default test duration in seconds (`15`, `30`, `60`, `120`).
- `caret_style`: Caret animation style (`SMOOTH_LIQUID`, `BLOCK`, `UNDERLINE`).
- `sidebar_collapsed`: UI navigation rail state (`true`, `false`).

## 5. JPA Entity Mapping Standards

Because SQLite has dynamic typing (type affinity), Hibernate entity mappings must declare explicit JDBC type codes to prevent schema validation mismatch:

```java
@Entity
@Table(name = "typing_sessions")
public class TypingSessionEntity {

    @Id
    @JdbcTypeCode(SqlTypes.VARCHAR)
    @Column(name = "id", nullable = false, unique = true, columnDefinition = "TEXT")
    private UUID id;

    @Column(name = "gross_wpm", nullable = false)
    private double grossWpm;

    @Column(name = "net_wpm", nullable = false)
    private double netWpm;

    @Column(name = "accuracy", nullable = false)
    private double accuracy;

    @Column(name = "total_errors", nullable = false)
    private int totalErrors;

    @Column(name = "raw_characters", nullable = false)
    private int rawCharacters;

    @Column(name = "correct_characters", nullable = false)
    private int correctCharacters;

    @Column(name = "duration_seconds", nullable = false)
    private double durationSeconds;

    @Column(name = "passage", nullable = false, columnDefinition = "TEXT")
    private String passage;

    @JdbcTypeCode(SqlTypes.VARCHAR)
    @Column(name = "completed_at", nullable = false, columnDefinition = "TEXT")
    private Instant completedAt;

}
```

## 6. Data Integrity & Concurrency Controls

1. **Idempotent Session Submission:** The `id` primary key is generated by the client before submission. If network retry occurs, `TypingSessionService.submitSession()` checks for existing `id` and returns the existing record without duplicate insertion.
2. **Connection Serialization:** SQLite writes are serialized with Hikari `maximum-pool-size: 1` to eliminate deadlocks.
3. **Transaction Boundaries:** Transactions are kept short and confined to service methods with `@Transactional`.
4. **Client-Side Outbox:** If the backend is temporarily offline during shutdown, the frontend retains completed sessions in IndexedDB (`typing_sessions_outbox`) and submits upon reconnection.
